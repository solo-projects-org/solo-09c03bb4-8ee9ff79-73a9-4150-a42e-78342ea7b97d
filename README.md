# 污水排放整升日档

按分钟记录毫升的污水监测数据，归档为整升日档。首次归档与补正共用一条误差规则：

> 对归档日的**任意连续时段** `[i, j]`，`|整升合计 × 1000 - 毫升原表合计| < 1000` 毫升。

补正时只能从某一分钟起覆盖到日末；系统在满足误差要求的所有整升结果中，
**尽量多保留现行档开头连续不变的分钟**，并在网页标出最晚重发起点。

## 启动

```bash
docker compose up --build
```

打开 <http://localhost:8000>。数据库保存在命名卷 `archive-data` 的
`/data/archive.db`。

不用 Docker 时：

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

可用环境变量 `DATABASE_PATH` 指定 SQLite 文件位置（默认 `./data/archive.db`）。

## 使用

1. **首次归档**：上传单日 CSV。分钟号必须连续升序，排水量为非负整数毫升。
   支持表头 `date,minute,ml`、`minute,ml`，以及 `日期,分钟号,毫升` 等中文别名；
   无表头时按 2 列或 3 列解析。日期可来自 CSV 或表单。
2. **下载**：日档页可下载整日整升 CSV（`date,minute,litre`）。
3. **补正**：在日档页上传与现行档**同一批分钟**的全表。页面显示最晚重发起点、
   保留前缀长度、整升变化行与最大连续时段差；确认后才换档。确认时可下载
   该起点至日末的整升 CSV。
4. **全表不变**：若上传的毫升全表与现行档记录的原表指纹一致，页面提示无需重发，
   不生成也不替换任何方案；若当天已有待确认方案，该方案原样保留，可继续确认。
5. **毫升有变、整升不变**：若原表指纹不同但算出的整升档与现行档完全一致，页面提示
   “整升档无需重发”，仍可点“确认仅更新原表记录”：整升行不动，版本号与原表指纹更新，
   并留一条零变动分钟的补正记录。
6. **核对后现行档已变**：保存方案与确认方案都在同一个 SQLite `BEGIN IMMEDIATE`
   事务内重新校验版本与指纹；不匹配则返回 409“请重算”，旧方案不会发布，保存阶段
   冲突时也不会删除已有的待确认方案。
7. **同天多份补正表并发核对**：校验 CSV 与整升计算都在写事务外完成，不阻塞别人确认；
   两份都基于同一现行版本的有效方案，以后提交保存者为准（旧编号确认时会提示重算）。
   方案刚保存就被更新的保存替换时，核对请求正常返回页面而不是 500。

网页首页带试用样例：可直接“载入样例首次归档”，再下载/上传样例补正表。
样例文件也在 `samples/` 目录。

## 设计要点

- 归档库只存整升（`minutes` 表只有 `minute` 与 `litre`）；上传的毫升原表仅在请求
  内存中校验，另存 SHA-256 指纹用于识别“全表不变”。
- 首次归档把累计误差保持在 `[0, 999]` 毫升内，因而任意连续时段误差 `< 1000`。
- 补正前缀可行性：固定前缀 `0..p-1` 的整升值时，前缀累计误差的极差必须 `< 1000`；
  满足此前缀即可用“减去余数、低于前缀最小值时进位”的方法补完至日末。
  因此 `p` 的最大值可由一次线性扫描求出，且结果可证明为最优。
- 误差核对使用前缀和 + 区间极差，一次扫描覆盖全部 `n(n+1)/2` 个连续时段；
  测试里用独立的 O(n²) 检查器交叉验证。

## 测试

```bash
pip install pytest httpx
python -m pytest tests/ -q
```

覆盖：首次归档不变量、补正前缀最优性（与暴力解对拍）、CSV 校验、Web 全流程、
下载内容、全表不变提示、“仅更新原表记录”、换档失效/重算保护、同表上传保留待确认
方案、过期保存不得覆盖新方案，以及多线程并发核对/确认不出现 5xx 与锁阻塞。

## 已知限制

- 单用户/小团队量级：SQLite 单库，未做登录鉴权与多租户隔离。
- 补正方案（preview）保存在数据库中，同一日只保留一个有效方案：基于同一现行版本
  再次生成会替换旧方案（后保存者为准）；同表上传或过期保存不会替换它。未做过期清理任务。
- 分钟号限制在 0–1439，单日最多 1440 点；不支持跨日或非整日区间归档。
- 容器镜像未在本机实际构建（环境无 Docker），但已提供可用的 Compose 配置与
  Dockerfile，并用同等依赖在本机以 uvicorn 实测。
